# Admin UI

[English](../admin-ui.md) | Русский

Web-интерфейс для просмотра процессов и ручного вмешательства. По умолчанию выключен; для включения задайте
`ruslo.admin-ui.enabled=true`. Подключение, настройки и защита через
Spring Security описаны в [README модуля](../../ruslo-admin-ui/README.md).

## Что можно делать

- **Дашборд** (`/ruslo`): счётчики `FAILED`, просроченных и `ACTIVE` процессов, у каждого definition — те же
  счётчики по его типу, а также зарегистрированные инстансы движка (узлы с запущенным диспетчером), число
  захваченных ими процессов и срок регистрации. Просроченный — процесс в `ACTIVE`, следующий запуск которого прошёл больше
  минуты назад, как и в карточке процесса. Клик по счётчику открывает список процессов с соответствующим фильтром. Дашборд
  обновляется раз в 5 секунд. Пустой список инстансов значит, что диспетчер не запущен ни на одном узле.
- **Список процессов** (`/ruslo/processes`): фильтры и запуск нового процесса.
- **Карточка процесса**: статус, состояние с описанием, переменные, последняя ошибка, история и схема с
  пройденным путём. Следующий запуск (шаг, повтор, сообщение в очереди или таймер) показан относительно текущего
  времени («in 2m»); у процесса в `ACTIVE`, следующий запуск которого прошёл больше минуты назад, он выделен как
  просроченный: диспетчер не забирает процесс. Пока процесс не
  завершён, карточка раз в 5 секунд проверяет изменения и перерисовывается только при них; при открытом диалоге или
  меню, а также в фоновой вкладке проверка пропускается. В истории отмечены текущее состояние и ручные переходы.

Действия собраны в меню Actions карточки процесса. Меню всегда показывает все действия: недоступное для текущего
процесса неактивно и подписано, почему (Retry — только для `FAILED`, Send message — только в ожидании, объявившем
сообщения). Действия соответствуют [операциям ручного вмешательства](operations.md#ручное-вмешательство):

| Действие | Что делает |
|---|---|
| Retry current step | `resumeFailedProcess`: повторяет упавший шаг или событие процесса в `FAILED` |
| Change state | `moveProcessToState`: переводит процесс в выбранное состояние; очередь сообщений сбрасывается |
| Send message | принимает JSON, проверяет его по классу payload и сохраняет как `sendMessage`; доступно в ожидании, объявившем сообщения, в том числе в `FAILED` |
| Add / edit / remove variable | меняет переменные процесса |

Retry и удаление переменной спрашивают подтверждение. Каждое действие пишется в лог приложения вместе с именем пользователя. Если действие не удалось, диалог остается
открытым и показывает ошибку.

Отправка сообщения подтверждает его сохранение, а не вызов обработчика: те же [гарантии](guarantees.md#сообщения),
что у `sendMessage`. Содержимое очереди сообщений и их историю Admin UI не показывает.

## Схема процесса

Схема строится автоматически из definition: состояния подписываются `ProcessState.description()`, рёбра — outcome,
именем сообщения, `every 30s`, `after 7d` или `at dueDate`. В карточке процесса подсвечиваются пройденные состояния и текущее состояние;
переход, сделанный вручную вне объявленных, рисуется пунктиром. Обозначения — в
[README модуля](../../ruslo-admin-ui/README.md#process-diagram).
