# Шаги

Шаг (`step`) выполняет код обработчика и сразу переходит дальше по состояниям процесса, объявленным в `ProcessDefinition`.

## Линейный шаг

Линейный шаг реализует `ProcessStep`. После `ProcessStep.execute()` движок переводит процесс в следующее состояние:

```java
.step(CREATED, OrderDefinition::reserveItems, WAITING_FOR_PAYMENT)

static void reserveItems(ProcessContext context) {
    var order = context.getVariable(ORDER).orElseThrow();
    // зарезервировать товары заказа
}
```

## Ветвящийся шаг

Ветвящийся шаг реализует `BranchingStep<O>` и возвращает константу enum `O`, а описание сопоставляет каждой
константе состояние:

```java
enum Validation { VALID, REJECTED }

.step(VALIDATING, validateStep, routes -> routes
    .on(Validation.VALID, RESERVING)
    .on(Validation.REJECTED, CANCELLED))
```

Компилятор проверяет, что маршруты используют enum шага, а `build()` — что для каждой константы задан маршрут.
Результатом выражайте ожидаемые бизнес-ситуации (заявка отклонена, карта не прошла). 
Исключение из обработчика движок воспринимает скорее как техническую ошибку, см. [error-handling.md](error-handling.md).

Шаг, целью которого указан он сам, выполняется снова ([переход в то же состояние](processes.md#переходы)).

## Worker шага

Шаг выполняется на worker процесса (`defaultWorker(...)`, по умолчанию `DEFAULT`) или на worker, переданном сразу
после состояния:

```java
.step(EXPORTING, IO_WORKER, exportDocumentStep, COMPLETED)
```

Режим worker определяет, в какой транзакции выполняется шаг:

- на транзакционном worker (`DEFAULT`) код шага и сохранение перехода выполняются в одной транзакции: изменения в БД
  приложения фиксируются ровно один раз вместе с переходом;
- на нетранзакционном worker код шага выполняется вне транзакции движка и не держит соединение с БД; изменения в БД
  приложения повторяются при повторе шага.

Шаги, работающие с БД, оставляйте на `DEFAULT`. Долгий внешний вызов выносите в отдельный шаг на нетранзакционном
worker. Режимы, регистрация и выбор `max-concurrency` — в [workers.md](workers.md).

## Повторное выполнение

Внешний вызов из шага выполняется **хотя бы один раз** в любом режиме worker. Если узел упал или транзакция
откатилась после HTTP-запроса или отправки в Kafka, шаг выполняется снова. Поэтому:

- делайте внешние вызовы идемпотентными, например передавайте ключ идемпотентности из переменных процесса;
- не полагайтесь на то, что шаг выполнится ровно один раз, даже если он не упал.

Повтор после исключения задаёт [политика ошибок](error-handling.md); номер попытки доступен через
`ProcessContext.attempt()`. Шаг может выполниться повторно и без исключения: если узел
упал или завис посреди шага ([dispatcher.md](dispatcher.md#падение-узла)).
